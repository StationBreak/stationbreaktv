# Bundled channel marks

Provenance and pipeline for the channel marks in `core/ui`. The checked-in hashes are in `channelmarks.sha256`
(sha256sum format, paths relative to `core/ui`); `ChannelMarkManifestTest` fails if a bundled file stops matching,
and also if any file under a `src/*/assets/channelmarks/` folder of any module in the repo (Android merges assets across
modules), or a symlink there, is missing from the manifest. Dot-folders and `build/` are skipped at the repo walk.

## What they are

- 106 fictional in-app channels, one mark each: the 102 recipes of the channel catalog and its four catch-all channels
  (the Kids, Family and Teen Odds & Ends, 33, 66 and 99, and Odds & Ends, 199). Not the StationBreak company brand.
- Nine of them are temporary placeholders (initials on a colour plate, made for catalog 8, #1002) until Look draws
  the real marks: Big Screen Toons, Starship Sunday, Prime Time Pals, Family Odds & Ends, Homeroom, Level Up, Popcorn
  Epic, Nervous Laughter and Teen Odds & Ends. They are not made by the generator in `scripts/channelmarks/v2/`.
- Made for this project: designed in the StationBreak brand session under the owner's direction, with AI assistance,
  and approved by the owner band by band. Each mark is a flat picture plus the channel's name, drawn as
  code in `scripts/channelmarks/v2/`; the rules are in `docs/design/channel-identity.md`.
- Licence: GPL-3.0-or-later WITH AdditionRef-StationBreak-AppStore, the project's licence (the marks are project art,
  not third-party art). See ADR-0003.
- They replace the typographic marks generated by `scripts/channelmarks/brands.py` from `brands.json` (2026-11-08), which
  are removed with their generator.

## The pipeline

```
scripts/channelmarks/v2/round1.py … round6.py, rabbit.py  (the marks as code: shapes, outlined text, colours)
        |
        v   scripts/channelmarks/v2/build.py   (fonttools, skia-pathops)
SVG masters, text converted to outlines       scripts/channelmarks/v2/out/svg/ and svg-mono/ (not committed)
  + contact sheet                              scripts/channelmarks/v2/out/contact-sheet.html (committed)
        |
        v   build.py --png   (rsvg-convert)
PNG renders, transparent, 48 dp and 64 dp at 2x  core/ui/src/main/assets/channelmarks/
```

- **Masters.** One 200 by 112 viewBox per channel (the 50 by 28 dp box at 4 px per dp, safe area 176 by 88), in colour
  (`svg/`) and with every fill white (`svg-mono/`). They are regenerated by the build, so only the contact sheet that
  shows them is committed.
- **Fonts.** Used only by the generator to draw the text, then outlined: no font file is in the APK, and no text is left
  in an SVG. The shared faces are in `scripts/channelmarks/fonts/` and the six added for these marks (Corben, Limelight,
  Rye, Shrikhand, Stardos Stencil, Yellowtail) in `scripts/channelmarks/v2/fonts/`. Each is SIL OFL 1.1 or Apache 2.0,
  with its licence in the `licenses/` folder beside it; `scripts/channelmarks/README.md` lists which is which.
- **Renders.** A bucket is N dp at 2x, so `_48dp` is 96 by 54 px and `_64dp` is 128 by 72 px (the 200:112 box). RGBA,
  under 16 KB each (about 1.4 to 6 KB). The build strips everything but the `IHDR`, `PLTE`, `tRNS`, `IDAT` and `IEND`
  chunks.
- **Renderer.** Renders are made by `build.py --png` with `rsvg-convert` (librsvg). The shipped set was rendered with
  rsvg-convert 2.58.0, and the same version reproduces `channelmarks.sha256` byte for byte. Another librsvg version
  may change the PNG bytes slightly; regenerate the manifest then.

### File names

| File | What |
|---|---|
| `sl_<NNN>_<key>_<N>dp.png` | the colour render |
| `sl_<NNN>_<key>_mono_<N>dp.png` | the same mark with every fill white |

`<NNN>` is the channel's catalog number and `<key>` its recipe or leftovers key; `CatalogMarksDriftTest` (in `core:domain`) checks both
ways that every catalog key has a mark and every mark is for a catalog key, with the number matching. `<N>` is 48 or 64.
Four files per key, 424 in all; `ChannelMarkManifestTest` checks the count, the pixel sizes, the PNG chunks and the size.

## How the app uses them

`AssetMarkLoader` lists the folder once, and for a key and a screen density decodes the smallest bucket whose pixels
(2N across) cover the 50 dp box, else the largest there is:

| Density | Needs | Bucket |
|---|---|---|
| up to 1.9x | up to 95 px | 48 dp (96 px) |
| 2x and above | 100 px and up | 64 dp (128 px) |

- **Dark** draws the colour render as it is.
- **Light** draws the mono render tinted with ink (`GuideColors.Light.markTint`), so every mark is one dark shape on the
  near-white page.
- `MarkCache` holds each variant separately and only decodes the one the current theme draws.

## Rule

Marks load only from the APK. Never from the server, the network or user content.

Known gap: Android also merges `assets/` from dependency AARs, which the repo scan cannot see; a check of the merged
assets in the built APK against this manifest is a tracked follow-up.

## Updating

1. Change the mark in its round file in `scripts/channelmarks/v2/` (or add one for a new catalog channel), following
   the rules in `docs/design/channel-identity.md`. Needs `pip install fonttools skia-pathops` and `rsvg-convert`
   (librsvg) on the PATH.
2. Regenerate the masters, the contact sheet and the renders from the repo root:

   ```
   python3 scripts/channelmarks/v2/build.py --png core/ui/src/main/assets/channelmarks
   ```

   Review `scripts/channelmarks/v2/out/contact-sheet.html` (the guide-size and one-colour strips) before accepting a
   mark.
3. Regenerate the manifest:

   ```
   cd core/ui && sha256sum src/main/assets/channelmarks/*.png | LC_ALL=C sort -k2 > channelmarks.sha256
   ```

4. Run `./gradlew :core:ui:testDebugUnitTest :core:domain:test`, and commit the round file, the contact sheet, the
   renders and the manifest together. A channel added to the catalog without a mark fails `CatalogMarksDriftTest`.
