# Back and Select audit

Read-only map of what Back and Select do in the Fire TV / Android TV app, from `src/main` only. Select here is `Key.DirectionCenter`, `Key.Enter`, and `Key.NumPadEnter` (the Compose names for DPAD_CENTER, ENTER, and NUMPAD_ENTER), plus `onClick` on a focused TV control.

There is one activity, `MainActivity`. It does not override `onBackPressed`. There is no `OnBackPressedCallback` subclass. No `src/main` file calls `onLongClick`, `combinedClickable`, or a long-press detector. A held Select or Back is not a second gesture: live TV re-sends only a held flip or seek (`feature/live/src/main/kotlin/tv/stationbreak/feature/live/ui/LiveKeys.kt:217-226`).

Shared policy, used by the guide, channels, the builder, and settings (`core/ui/src/main/kotlin/tv/stationbreak/core/ui/RemoteKey.kt:14-47`):

- Select is `DirectionCenter`, `Enter`, and `NumPadEnter`, and it acts on the first key-down.
- Back acts on key-up.
- A direction outside the screen's pad set is consumed and does nothing.

Live TV does not use that function. See Findings.

The graph comment says Back goes up one level and, from the only stack entry, leaves the app (`app/src/main/kotlin/tv/stationbreak/app/nav/AppNavHost.kt:48-50`). Routes reached with `replaceAll` have nothing under them (`AppNavHost.kt:360-362`). There is no "exit the app?" confirm. The channel builder does confirm leaving unsaved work.

The ready notice drawn over live TV takes no focus and no key (`app/src/main/kotlin/tv/stationbreak/app/nav/ReadyNoticeHost.kt:16-29`). There is no direct channel-number entry on live TV. Up and Down flip (`feature/live/src/main/kotlin/tv/stationbreak/feature/live/ui/OverlayKeys.kt:51-53`). Digits exist only on the Kids PIN pad and the channel-number picker.

## Findings

Verified from the handlers above. No dead end: every state that consumes Back either steps inward, dismisses what is open, or leaves the app. The sign-out in-flight row ignores Back until the call returns; that wait is the only Back that neither moves nor leaves, and it is temporary (`SignOutViewModel.kt:136-138`).

1. Live TV's Select map omits `NumPadEnter`, and its Back runs on key-down. The shared policy does the opposite. `remoteKeyOf` maps `DirectionCenter`, `Enter`, and `NumPadEnter` to Select, and `remoteKeyToAct` runs Back on key-up (`RemoteKey.kt:20`, `RemoteKey.kt:44`). The guide's Select set is those same three keys (`GuideDestination.kt:659`). Live's overlay map handles only `DirectionCenter` and `Enter` (`OverlayKeys.kt:60`). `NumPadEnter` therefore does not show the banner and does not play while paused (`LiveKeys.kt:196-207`). Live runs the mapped action, including Back, on key-down and only swallows the key-up (`LiveKeys.kt:197-207`). Guide, channels, the builder, settings, the PIN pad, hours, and PIN reset all go through `remoteKeyToAct`.

2. Back leaves the app from the guide while it is still loading. `GuideViewModel.back()` returns false when the state is not Ready and not Empty, the menu is closed, and there are libraries (`GuideViewModel.kt:678-680`, `GuideState.kt:20-23`). The screen then dispatches `onBackPressed()` (`GuideDestination.kt:403-404`). On Ready, that same Back jumps to the playing cell or opens the menu (`GuideViewModel.kt:688-695`). On Empty, it opens the menu (`GuideViewModel.kt:641-646`).

3. Back on "Signed in as" finishes the activity while the library picker is still underneath. The route's `BackHandler` calls `activity?.finish()` (`AppNavHost.kt:262-266`). Back from the picker navigates forward to this screen instead of popping (`AppNavHost.kt:251-254`). Continue is the control that pops (`AppNavHost.kt:268`).

4. Back on first sync leaves the app, except during the cheer. The route is installed with `replaceAll` and has no `BackHandler`; the graph comment says Back exits and the sync keeps running (`AppNavHost.kt:255-256`, `AppNavHost.kt:280-284`). The cheer consumes Back and, on key-up, continues to live TV (`FirstSyncScreen.kt:159-169`).

5. Back on the opening finishes the activity until launch routing has a destination, then skips. Both paths were the same cover (`AppNavHost.kt:100-101`). Fixed in #1084: Back is consumed and does nothing until routing has a destination.

6. The same list-screen key handler is copied for Pro and for settings Libraries. `ProActions.pad` (`ProDestination.kt:98-118`) and `LibrariesActions.pad` (`LibrariesDestination.kt:74-93`) are the same Up / Down / Select / Back-finishes-once structure. `padToAct` is also declared twice: settings limits the pad to Up and Down (`Pad.kt:29-40`); channels passes every direction through (`ChannelsDestination.kt:236-244`). Sign-in registers two `BackHandler`s (`AppNavHost.kt:237-238` and `SignInScreen.kt:138`). While Quick Connect is showing, Back cancels Quick Connect and stays on the form (`SignInScreen.kt:56-57`).
